# Nota 最小可用版本（MVP）需求文档

> 来源：题目截图（2026-11-06）。目标：做一个 Nota 的**最小可用版本**，能真实体验「说一段话（或输入一段文字）→ AI 整理出摘要和待办，并帮用户把事情办了」。

## 0. 交付分档

| 档位 | 说明 |
| --- | --- |
| **基础交付** | 必须完成 |
| **加分项** | 做多少算多少，不做不扣分 |

## 1. 基础交付（必须完成）

### 1.1 可运行的网页版本
- 前端：纯 HTML 或任意前端框架均可。
- 后端：Python 或 Node.js。
- 前后端配合，可本地运行、可演示。

### 1.2 核心处理由 AI Agent 完成
- Agent 能根据用户说的话，**自主决定**调用设计好的工具，而不只是一次文本生成。
- 工具**至少 2 个**，例如：
  - 创建待办
  - 设置提醒
  - 查询历史记录
- 工具由自己设计，数量与能力可扩展。

### 1.3 Free 用户每天 10 次的额度限制
- 实现 Free 用户每日 10 次使用额度。
- **要求在真实使用环境下依然准确**（防刷新、防多端、防重启丢失计数等）。
- **需要自己想办法证明这一点**（如测试用例、演示脚本、评测结果）。

### 1.4 README
- 如何运行。
- 架构与关键取舍，**300 字以内**。

## 2. 加分项

1. **App 版本**：React Native 或 Flutter。
2. **硬件联动**：用 ESP32、树莓派等实物，或 Wokwi 等仿真器，与系统打通。
3. **讲清楚网页、App、硬件三者的关系与交互流程**（架构图、时序图均可）。即使没有全部实现，讲清楚也加分。
4. **Agent 进阶**：
   - 调用过程在界面上可见；
   - 能基于用户的历史记录回答问题；
   - 有自己的一套效果评估方法或测试样例。
5. 任何自己认为对这个产品重要、但题目没有要求的东西。

## 3. 规则

- 后端使用 Python 或 Node.js；如做 App，使用 React Native 或 Flutter；其他技术选型不限。
- 允许使用一切在线资源与 AI 工具（Part B）。
- 大模型自选，推荐国内模型：Kimi（月之暗面）、智谱 GLM、DeepSeek、通义千问等（新用户一般有免费额度）；**所选模型需支持工具调用（function calling）**。
- 仓库中提供 `.env.example`；模型 API Key 自行申请，**官方不提供 key**，也**请勿把真实 key 提交到仓库**。

## 4. 验收清单（自查）

- [ ] 网页 + 后端可一键跑起来，能完成「输入 → 摘要 + 待办 → 事项被办理」闭环
- [ ] Agent 至少 2 个工具，且由模型自主决定调用（非固定流程）
- [ ] Free 每日 10 次额度在真实环境下准确，且有证明材料
- [ ] README 含运行方式 + 300 字内架构与取舍
- [ ] `.env.example` 在仓库中，真实 key 不入库
